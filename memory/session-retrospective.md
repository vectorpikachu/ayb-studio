# 这段开发过程的复盘

> 记录的是“为什么最后长成这样”，不是 changelog。changelog 看 `git log`。

## 1. 时间线

### 阶段一：先把旧任务收尾

- 用户要求先停下之前的事，有修改就 commit。
- 工作树清理后，进入 Liquid Glass 重做。

### 阶段二：视觉重做

- 从普通卡片改成暖纸色 + 玻璃面板 + 石榴红/杏色光场。
- 建立 `.glass` / `.surface-card` / `.glass-soft` / `.modal-glass`。
- 导航改成悬浮胶囊；移动端改底部 Dock。
- 这个阶段的核心不是“加模糊”，而是让玻璃有纸感、有内描边、有克制的动效。

### 阶段三：Docker / 桌面端的弯路

- 曾尝试 Docker Desktop 验证生产容器，机器没装 WSL，Windows Home 也不能用 Hyper-V 后端。
- 用户明确说不要 Docker、不要 exe，只要网站。
- 删掉 Dockerfile、compose、electron、desktop CI、图标等，回到 `npm run build && npm start`。
- **教训**：不要在用户只要网站时，先上容器/桌面打包这种“完整交付”的执念。

### 阶段四：手写体的三次迭代

1. **Tumanian**：太狂放，不像规整手写。
2. **First Time Writing**：用户评价“这不是手写体，是手写体风格的印刷体”。
3. **Poqrik dzeragir**：真正的亚美尼亚连笔；最终采用。

中间还踩了 `next/font` 的坑：拉丁字符 fallback 到 Noto Sans，导致手写串里混印刷体。最后改成手工 `@font-face` + `unicode-range`，把亚美尼亚字母和拉丁字母拆成两个 face。

后来又发现字母卡只有小写手写，补上大写 + 小写。

### 阶段五：语法顺序

- 原来第 9 课只讲五个高频格后缀，第 10 课直接进关系从句。
- 用户问：“亚语明明这么多的格啊什么的，你这语法怎么开始讲别的了。”
- 加了两节 B1：
  - 第 10 课：七个格全景；
  - 第 11 课：词干、复数、例外、后置词。
- B2 顺延到 12–15。
- 现在 B1 是 3 节连续的格系统课。

用户后来问“不是有十二种格吗？”——这次没有改课程，而是解释 7 格标准、6 格分析、12 的常见来源。**不能为了顺从而把事实改错。**

### 阶段六：课文从 1 到 3，再到“写厚”

- 最初只放了《我的早晨》一篇 A2。
- 用户问：“为什么就一篇课文？像亚美尼亚创伤这个阿博维扬写的不是可以去摘抄吗？”
- 加了阿博维扬序言选段 + 恰连茨短诗。
- 用户又问：“后面两篇课文为什么就这么一点点？”
- 把阿博维扬扩成 5 段 / 126 词，恰连茨扩成全诗 4 节 / 127 词；加现代亚美尼亚语改写、翻译、生词、语法、换行保留。
- **教训**：文学内容不能用“一句名言 + 两行诗”充当课文；用户要的是可读的文本。

### 阶段七：文化栏目 + 管理员

- 用户要求加历史/文化/人物/地理栏目，并且管理员能增删改。
- 做了 11 条文化条目。
- 做了 `/admin/library` JSON 编辑器：
  - 新建、修改、删除、下载；
  - 同 id 覆盖内置；
  - 删除覆盖恢复内置；
  - 课文/文化详情页改成动态，保证管理员修改立即生效。
- 这里的关键设计是 **static seed + custom override**，而不是把种子内容搬进数据库。

### 阶段八：数字与品牌

- 文化卡片里的 `1915 թվական` 中，`1915` 落到了 First Time Writing 的拉丁手写数字，和亚美尼亚连笔不搭。
- 修复：
  - 把数字从拉丁手写 face 的 unicode-range 里排除；
  - 数字回退 Noto Sans Armenian；
  - 文化标题用 `HandText` 把数字缩到 `0.78em`。
- 又发现 favicon/PWA/Apple 图标还是拉丁 A，页头却是亚美尼亚 `Ա`；全部换成从 Noto Sans Armenian 提取的 `Ա` 路径。

## 2. 做错的地方与根因

| 问题 | 根因 | 现在的规则 |
| --- | --- | --- |
| 手写体像印刷体 | 把“手写风格”当成了“手写脚本” | 必须用真正的连笔亚美尼亚字体 |
| 只有小写手写 | 只检查了字母存在，没有检查大小写 | 字母卡必须大写+小写 |
| 先上 Docker/Electron | 把“完整交付”理解成桌面/容器 | 只要网站，`build && start` |
| 课文只有一篇/一句 | 用 demo 心态做内容 | 文学选读要有厚度、来源、翻译、词汇、语法 |
| 数字混拉丁手写 | 假设手写字体有数字 | 数字固定印刷体；`HandText` 控制大小 |
| favicon 是拉丁 A | 只改了页头，没有检查图标资产 | 品牌字形统一到所有 icon |
| 管理员改内容不生效 | 详情页 `generateStaticParams` 静态化 | 可编辑内容页面必须动态 |
| 768 导航重叠 | 6/7 项导航在 `md` 就展开 | 桌面导航 `lg` 起，以下用 Dock |
| E2E 删除偶发失败 | 删除后立刻跳转，数据未落盘 | 等待 1500ms / 独立数据目录 |

## 3. 做对的地方

- **先确认用户边界**：不要 Docker、不要 exe，直接改回网站。
- **字体分层**：Noto 负责可读性，Poqrik 负责手写识别，First Time Writing 只做拉丁注释。
- **内容与 UI 分离**：种子在 `src/data`，覆盖在 DB，管理员不用改代码。
- **生产模式验证**：不只跑 dev；`npm run build` + `npm start` + `npm run qa`。
- **截图验证**：1440/390 都看；768/1024 专门查导航。
- **直接读原文**：阿博维扬从 Wikisource 序言取原文，不凭记忆编。
- **把用户的原话变成规则**：这份 memory 的大部分条目都来自具体纠正，不是抽象原则。

## 4. 已知的未完成/待核对

- **恰连茨文本拼写**：Wikisource 作 `արևահամ բարն`，常见版本作 `արևահամ բառն`；当前用 `բառն`。正式发布前应找权威版本核对，并在来源处说明版本差异。
- **阿博维扬译文**：中文是学习性意译，建议母语者/文学译者复核。
- **文化栏目历史表述**：1915 等条目应请历史方向的人复核措辞。
- **管理员 CRUD 未进 E2E**：目前只手工/API 测过课文与文化的创建-覆盖-删除。
- **管理员编辑器是 JSON**：功能完整，但对非技术管理员不够友好；未来可以加表单模式。
- **阅读课没有测验**：目前是阅读 + 生词 + 语法，没有课后题。
- **朗读依赖浏览器语音**：没有亚美尼亚语音频文件，质量取决于系统 voice。
- **更多课文**：当前 3 篇；数据模型支持继续加，管理员也能加。

## 6. 如果重新开始，会怎么做

1. 先确认“只要网站”，不碰 Docker/Electron。
2. 先定字体策略：Poqrik 主体 + Noto 印刷 + 数字单独规则，再写页面。
3. 语法先画 7 格地图，再排 B2。
4. 课文先定“每篇至少 3–5 段/节 + 生词 + 语法 + 来源”的验收线，再写第一篇。
5. 内容模型一开始就做 static seed + custom override，避免后面补管理员。
6. 品牌字形（页头、favicon、PWA、Apple）一次统一。
7. 每个阶段都用生产模式 + 390/768/1024/1440 截图验收。
