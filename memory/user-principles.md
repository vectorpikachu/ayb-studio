# 用户准则与偏好

> 这些是从实际对话里提炼出来的，不是泛泛的“用户喜欢好设计”。

## 1. 产品边界

- **只要网站，不要桌面端/容器**：不装 Docker、不做 Electron、不出 `.exe`。
- 部署命令就是 `npm run build && npm start`；前面可以反向代理，但不要为了部署把功能砍成静态站。
- 用户原话：“我现在不想装这个 docker，能不能不用 docker，我就不要这个 exe 之类的了，单纯是一个网站。”

## 2. 手写体

- 必须是**真连笔的亚美尼亚手写体**，不是“手写风格的印刷体”。
- 用户原话：“你这个也不是手写体啊，你这是手写体风格的印刷体好吗。”
- 手写要出现在实际语言材料旁边：单词、例句、字母、课文，而不是只做一个手写标题。
- 字母卡要**大写 + 小写**都展示；只做小写会被发现。
- 手写字体可以换，但不能牺牲“可辨认的连笔”这个核心。

## 3. 数字

- 数字不要用拉丁手写体混在亚美尼亚连笔里；用户原话：“和亚美尼亚语手写体放在一起的数字太难看了，比如这个 1915。”
- 正确做法：回退到 Noto Sans Armenian 印刷体；文化标题用 `HandText` 把数字缩到 `0.78em`。
- Poqrik 本身没有 0–9 字形，不要假装它有。

## 4. 语法

- 亚美尼亚语标准语法是 **7 个格**，不是 12 个。
- 用户问过“不是有十二种格吗？”——要解释 12 的常见来源（12 年级教材、变格类型、格+数组合），并说明 6 格分析存在，但 12 格不是通行分析。
- 语法顺序：A1 基础 → A2 时间 → B1 七个格与变格 → B2 句法。不能从“五个高频后缀”直接跳到关系从句。
- 用户对“格”很敏感；涉及格的课程要有表格、例句、变格和例外。

## 5. 内容厚度

- 不要用“先放一篇/一句占位”的思路交付文学内容。
- 用户先问“为什么就一篇课文？”，再问“后面两篇课文为什么就这么一点点？”。
- 文学选读至少要有：原文、作者/作品/年份、中文翻译、生词、语法点、来源；古旧文本加现代亚美尼亚语改写。
- 诗要保留换行；不要把四节诗压成一段。
- 不要编造原文；公共领域也要给出处。

## 6. 管理员

- 用户明确要求：“这些栏目都是要管理员可以增删改的。”
- 不只是上传：要能新建、修改、删除；同 id 覆盖内置，删除覆盖恢复内置。
- 课文/文化详情页必须动态，管理员改完前台立即能看到。
- 管理入口要清楚：`/admin` 与 `/admin/library`。

## 7. 品牌与视觉

- Logo、favicon、PWA、Apple Touch Icon 都要用亚美尼亚字母 **Ա**，不能是拉丁 A。
- 页头品牌标记与 favicon 要是同一个字形。
- 用户对“小 logo 是 A、主页是亚美尼亚语”这种不一致很敏感。
- 视觉要暖、安静、有纸感；不要通用紫色渐变 SaaS 模板。
- 用户会看细节：字母是否大小写、数字是否协调、导航是否挤、手机是否溢出。

## 8. 响应式

- 至少 390 / 768 / 1024 / 1440。
- 导航不能压住 logo 或右侧按钮；曾经在 768 出现重叠，后来改成 `lg` 才显示桌面导航，以下用 Dock。
- Dock 7 项也要能放下；不要出现横向滚动。

## 9. 事实与敏感内容

- 1915 相关内容要克制、事实、可核对，不搞宣传式语言，也不搞否认式语言。
- 文化栏目是编辑内容，发布前建议母语者/历史方向复核。
- 文学翻译标明是意译，建议母语者校对。

## 10. 协作方式

- 用户希望**直接执行**，不是先写一份很长的计划再问。
- 改完要**提交**；用户说过“有修改的就 commit 一下”。
- 解释要给出**根因**，不要只说“已优化”。
- 用户纠正事实时，先核对，再承认；不要为了顺从而改错内容。
- 不要反复问“要不要继续”；能做的先做完，再把选择权交给用户。
- 回复用中文为主；代码、路径、命令保留英文。

## 11. 用户不喜欢的交付

- 一句“已修复”但没有验证。
- 只有 dev 模式通过，没有生产构建/E2E。
- 只有桌面截图，没有移动端检查。
- README 数字与页面不一致。
- 用占位内容冒充完整内容。
- 为了“统一”把亚美尼亚语换成拉丁字母，或反过来。
